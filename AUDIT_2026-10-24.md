# Code review and production-readiness audit — 2026-10-24

Repository: `Bendako/next-starter-script` at main commit `7e9b8c647fa33633594b231f3e911c2b6449b8ce`.

## Scope and limitations

Static source inspection covered the Bash generator, MCP stdio server, hosted payments core, legacy Next.js/Express SaaS, tests, and CI workflow. GitHub Actions validated the two remediation PRs (see their CI tabs). This is **not** an independent penetration test, a deployed-service audit, or proof of successful project generation under every template. A full end-to-end deployment test and a dependency audit remain necessary.

The repository contains **three distinct maturity levels**:
- `create-next-starter.sh` + `mcp-server/`: actively tested local generator and stdio MCP integration.
- `hosted/`: payments core under development; OAuth, HTTP transport, provider adapters and delivery are spread across pending PRs.
- `web-app/`: older SaaS prototype with disabled/mocked authentication and incomplete database mapping. **Do not expose publicly.**

## Release gates (must pass before public hosted launch)

1. Require verified identity on every generation, status, download, and subscription endpoint; never trust a body `userId`.
2. Enforce limits on the backend and reserve/reconcile quotas atomically; rate limit both creation and artifact requests.
3. Run generation in an isolated and resource-limited sandbox (CPU, memory, disk, network policy, timeout) and clean up jobs.
4. Enforce payment webhooks with verified signatures, idempotency, schema-aligned updates, correct customer/account mapping, and test-mode end-to-end fulfillment.
5. Verify owned downloads with authorization or signed expiring URLs; test cross-account access.
6. Add integration tests for each supported template (generation, `npm ci`, lint, typecheck, build) and for MCP stdio and HTTP transports.
7. Disable build-error ignores, add web-app CI, rotate/remove any accidentally committed secrets, add LICENSE and accurate release docs.
8. Only then consider enabling production generation or checkout.

## Recommended implementation order

1. Merge **PR #34** after code review (hosted request isolation).
2. Review **PR #35** (legacy containment; **does not** restore production use).
3. Complete and review the hosted MCP HTTP and Clerk OAuth chain; avoid public endpoints until all guards are in place.
4. Implement authenticated sandbox generation and scoped artifact delivery.
5. Wire the new hosted payment provider and durable entitlement store with replay-safe webhooks.
6. Decide whether to retire the legacy `web-app/` or rebuild it using the hosted backend; do not duplicate payment/auth logic.
7. Run a real sandboxed end-to-end CI release checklist and a security review.
